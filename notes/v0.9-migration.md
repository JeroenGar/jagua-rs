# Migrating to jagua-rs 0.9

This release changes the shared input contract and Rust APIs. Reflections are not
included. Existing placement rotation and translation fields retain their meaning.

## Item rotations

Every item now requires an `orientation` object with an explicit `rotation`.
All angles are in degrees in the original item's coordinates.

| Permission | Rotation object |
| --- | --- |
| Fixed | `{"mode":"discrete","angles":[0]}` |
| Specific angles | `{"mode":"discrete","angles":[15,195]}` |
| Quarter turns | `{"mode":"stepped","step":90}` |
| Half turns | `{"mode":"stepped","step":180}` |
| Any angle | `{"mode":"continuous"}` |

For example, replace `"allowed_orientations": [0, 180]` with:

```json
"orientation": {
  "rotation": {"mode": "stepped", "step": 180}
}
```

Replace an omitted or null legacy orientation with explicit continuous rotation.
Replace an empty legacy list with discrete `[0]`. Legacy permission fields are
rejected, including when mixed with the new object. Unrelated item metadata is
still accepted.

Discrete lists must be nonempty and finite. Equivalent angles are normalized
modulo 360 and deduplicated. A stepped mode starts at zero, excludes 360, and must
divide a full turn. Lists and expansions are limited to 65,536 angles. The exact
step tolerance is documented on `ExtRotation`. No search or sampling mode changes
are required: stepped inputs compile into discrete rotations.

## IDs, geometry and separation

- Item IDs may be any unique `u64` values. Parsed instances map them to dense
  internal indices. Export preserves the external IDs; duplicate IDs are rejected,
  including on zero-demand entries.
- Item polygons with holes are rejected. Container holes remain supported.
- SPP, MSPP and BPP inputs accept `min_item_separation`, a finite nonnegative
  distance in input units. Omission means zero and null is invalid. Instance import
  applies it to both item and container geometry. Remove the old LBF config field.

## Rust consumers

The shared `Instance` trait is removed. Pass an item lookup to layout density
methods, and a lookup returning `(&Item, external_id)` to JSON and SVG exporters.
Concrete problem instances keep their `item(internal_id)` methods and expose
`external_item_id` and `internal_item_id`.

Concrete instance constructors now receive the sorted external-ID vector alongside
their items and containers. `Importer::import_item` receives an explicit internal
index. `Importer::new` no longer takes separation; direct geometry callers can use
`with_min_item_separation`, while problem import reads it from the input.
SPP warm-start import now returns a `Result` and rejects unknown external item IDs.

The in-repo LBF native and WASM consumers and bundled instances are migrated.
Adoption by vanilla sparrow and sparrow Pro is separate work after this stack is reviewed.
