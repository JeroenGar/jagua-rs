# jagua-rs 1.0.0

jagua-rs 1.0.0 changes both the JSON input format and the Rust API. Migrate
instances and calling code before upgrading from 0.8.x. The minimum supported Rust
version is now 1.90.

## Highlights

- Explicit orientation permissions: discrete, stepped or continuous rotation, with
  optional reflection axes.
- Layouts and snapshots share item definitions through `Arc<Item>`, so collision,
  density and export APIs no longer need an instance lookup.
- External item and bin IDs are kept separate from internal indices and are
  preserved through import and export.
- Item separation is part of the instance input rather than optimizer
  configuration.
- Strip construction, resizing and fitting return errors instead of producing
  invalid state.
- Coupled layout, geometry, snapshot and problem state is exposed through read-only
  accessors.
- Quality-zone filtering in collision checks is fixed, including zones that cover a
  complete quadtree node.

## Requirements

- Rust 1.90 or newer for the `jagua-rs` library.
- The workspace pins Rust 1.98.0 for development; the threaded WASM demo still
  builds with nightly for `build-std`.
- The workspace `Cargo.lock` is now tracked.

## Breaking JSON changes

### Item orientation

Every item requires an `orientation` object with a `rotation` field. Angles are in
degrees in the original item's coordinates.

| Allowed rotations | `rotation` value |
| --- | --- |
| None (fixed) | `{"mode": "discrete", "angles": [0]}` |
| Specific angles | `{"mode": "discrete", "angles": [15, 195]}` |
| Quarter turns | `{"mode": "stepped", "step": 90}` |
| Half turns | `{"mode": "stepped", "step": 180}` |
| Any angle | `{"mode": "continuous"}` |

Validation rules:

- Discrete lists must be nonempty and contain finite angles. Zero is not implicit.
  Equivalent angles are normalized modulo 360° and deduplicated.
- A stepped rotation starts at 0° and excludes 360°. Its finite step must be in
  (0, 360] and divide a full turn; the exact tolerance is documented on
  `ExtRotation`.
- Discrete lists and stepped expansions are limited to 65,536 angles.

Stepped rotations compile into discrete rotations, so optimizers need no new search
or sampling mode to support them.

### Reflections

`orientation.reflection_axes` optionally lists reflection axes, in degrees
counterclockwise from the item's local positive X-axis, through its local origin.
Omitting it or passing `[]` disables reflection. A placement uses either no
reflection or one of the listed axes, followed by an allowed rotation and then
translation. Axes that differ by 180° are equivalent.

This item may be placed as-is or mirrored left-to-right, with no rotation:

```json
{
  "id": 7,
  "demand": 2,
  "orientation": {
    "rotation": {
      "mode": "discrete",
      "angles": [
        0
      ]
    },
    "reflection_axes": [
      90
    ]
  },
  "shape": {
    "type": "rectangle",
    "data": {
      "x_min": 0,
      "y_min": 0,
      "width": 40,
      "height": 10
    }
  }
}
```

In placement output, `reflected: true` means reflection across the local X-axis
before `rotation` and `translation`; omitted means `false`. A reflection about input
axis `a` followed by rotation `r` is exported as `reflected: true` with rotation
`r + 2a` (mod 360°). For example, a Y-axis reflection followed by translation by
`(20, 5)` is exported as:

```json
{
  "reflected": true,
  "rotation": 180,
  "translation": [
    20,
    5
  ]
}
```

The 180° encodes the reflection; it does not grant an additional rotation
permission. Rotation and translation fields in placements otherwise keep their
0.8.x meaning.

Optimizers that search reflections must sample both permitted reflection states and
preserve the reflection state when refining a pose. Rotation-only optimizers can continue to search unreflected orientations.

### Migrating from `allowed_orientations`

| 0.8.x input | 1.0.0 `rotation` |
| --- | --- |
| Omitted or `null` | `{"mode": "continuous"}` |
| `[]` | `{"mode": "discrete", "angles": [0]}` |
| `[0, 180]` | `{"mode": "stepped", "step": 180}` or `{"mode": "discrete", "angles": [0, 180]}` |
| `[0, 90, 180, 270]` | `{"mode": "stepped", "step": 90}` |

`allowed_orientations` and its legacy aliases are rejected, including when present
alongside `orientation`. Unrelated item metadata, such as source file names, is
still accepted.

### Item separation

SPP and BPP instances accept a top-level `min_item_separation`: a finite,
nonnegative distance in input units. Omitted means zero; `null` is invalid. Import
applies it to both item and container geometry.

```json
{
  "name": "example",
  "min_item_separation": 0.5,
  "strip_height": 100,
  "items": [
    {
      "id": 0,
      "demand": 3,
      "orientation": {
        "rotation": {
          "mode": "stepped",
          "step": 90
        }
      },
      "shape": {
        "type": "rectangle",
        "data": {
          "x_min": 0,
          "y_min": 0,
          "width": 40,
          "height": 10
        }
      }
    }
  ]
}
```

Remove `min_item_separation` from LBF configuration files and set it in the
instance instead.

### IDs and geometry

- Item IDs may be any unique `u64` values; they no longer need to be dense or
  zero-based. Duplicate IDs are rejected, including on zero-demand entries.
- Bin IDs may be sparse and are preserved on export. Duplicate bin IDs are rejected
  before zero-stock bins are filtered out.
- Item polygons with holes are rejected. Container holes remain supported.
- Unsupported quality-zone shapes and invalid quality levels are import errors.
- Layout export writes `container_id` from an explicitly supplied external
  reference: `0` for the SPP strip, and the source bin's external ID for BPP. This
  is output metadata, not a collision-engine identity.

## Breaking Rust API changes

### Items, instances and placements

- The shared `Instance` trait is removed. Concrete instances store `Arc<Item>`, and
  their `item(idx)` methods return `&Arc<Item>`. Use `item_idx(external_id)` to
  resolve an external ID.
- `Item::new` takes both `idx` and `external_id`. `Importer::import_item` takes an
  explicit internal index, reads the external ID from the input and returns
  `Arc<Item>`.
- `PlacedItem` holds `item: Arc<Item>` instead of `item_id`. Use
  `pi.item().idx()` for indexing and `pi.item().external_id()` for export.
- Placement takes `&Arc<Item>` and shares it. When constructing items directly,
  wrap each in `Arc::new` once.
- Layouts and snapshots keep their items independently of the instance. Density,
  JSON export and SVG export no longer take an instance. `Layout::items()` iterates
  distinct item types.
- `Importer::new` no longer takes a separation. Direct geometry callers can use
  `with_min_item_separation`; problem import reads it from the instance.
- SPP/BPP problem placement requires remaining item demand and bin stock and panics
  when either is exhausted. Generic `Layout::place_item` does not track these quantities.

```rust
// 0.8.x
let item = instance.item(pi.item_id);
// 1.0.0
let idx = pi.item().idx();
let external_id = pi.item().external_id();
```

### Bins and containers

- Containers no longer have an ID. Bin types own `idx`, `external_id`, stock and
  cost.
- BPP problems and solutions keep an association from each layout to its bin
  index.

### Protected state

Coupled fields on `Item`, `PlacedItem`, `SPolygon`, `Container`,
`InferiorQualityZone`, `Layout`, `LayoutSnapshot`, `CDEngine` and the SPP/BPP
problem and solution types are now read-only through accessors:

```rust
layout.placed_items()
problem.layout()
problem.item_demand_qtys()
solution.layout_snapshot()
```

Drop borrows that become redundant where an accessor already returns a reference.
Mutate state through placement and removal, `Layout::swap_container` and problem
resize methods.

### Fallible strip and problem operations

- Strip-to-container conversion uses `TryFrom` instead of `From`.
- `SPProblem::new`, `SPProblem::change_strip_width` and `SPProblem::fit_strip`
  return `Result`. A failed resize leaves the problem unchanged, and `fit_strip`
  returns an error for an empty layout.
- For SPP, use `problem.change_strip_width(width)?` rather than assigning the strip
  and swapping the layout container separately. If an optimizer also moves items
  during a resize, keep its existing failure handling and collision-tracker update
  order.
- SPP solution import returns a `Result` and rejects unknown external item IDs.
- The LBF SPP optimizer's constructor and `solve` method return `Result`.

### Snapshots and restore

- `Layout::restore` returns `Result<(), ContainerMismatch>`. It requires the
  snapshot's container to share the same `Arc` base collision engine as the layout;
  containers with equal but independently constructed geometry do not qualify. On
  mismatch the layout is unchanged.
- To restore onto a different container, use `Layout::from_snapshot`, or call
  `layout.swap_container(snapshot.container().clone())` before `restore`.
- Problem-level restore handles saved strip widths and bins itself.
- `BPProblem::restore` may give recreated layouts new keys. Its `bool` return value
  reports whether layout keys changed; do not keep layout keys across a restore that
  returns `true`.

### Collision detection

- `Layout::is_feasible()` is renamed to `is_collision_free()`. It checks collisions,
  respecting item quality requirements; it does not check demand or orientation
  permissions.
- CDE snapshots, CDE save/restore and quadtree internals are now crate-private. Use
  layout snapshots and restore instead. Public collision queries and diagnostics remain available.
- Replace hazard-map indexing with `cde.hazard(key)`, which returns an `Option`,
  for example `cde.hazard(key).expect("registered hazard")`. Collector-based
  self-exclusion is still supported.
- To obtain a reusable collision-shape buffer, clone it with
  `item.shape_cd().as_ref().clone()` and keep its surrogate. `TransformableFrom`
  destinations must be initialized from the same reference geometry; a matching
  vertex count is not sufficient.

### Multi-strip packing

The `mspp` feature and `probs::mspp` module are removed. Multi-strip problems can be
implemented outside the library on top of the generic layout and collision-detection
APIs.

## Fixes

- Quality zones that meet an item's minimum quality are ignored by collision checks.
  Filtering such a zone no longer panics when it fully covers a quadtree node.
- Container holes block placement regardless of item quality.

## Upgrade checklist

1. Replace `allowed_orientations` with `orientation.rotation` and move
   `min_item_separation` from optimizer configuration into each instance.
2. Update item handling for `Arc<Item>`, `idx` and `external_id`, including
   placement, export and restore call sites.
3. Replace public field access with accessors, and route mutations through the
   provided methods.
4. Handle the new `Result` returns from import, strip and problem operations.
5. Re-test saved-solution round trips and your crate with the feature set it
   enables.

The bundled instances and the in-repository LBF native and WASM builds have been
migrated and can serve as examples.
