# jagua-rs 1.0.0

This release changes the JSON input contract and Rust APIs. Upgrade consumers before
replacing a 0.8.x dependency. Rust 1.90 or newer is required.

## Highlights

- Explicit discrete, stepped and continuous rotations, with optional reflection axes.
- Layouts share item definitions through Arc, so collision, density and export APIs
  no longer need an instance lookup.
- External item and bin IDs survive import/export independently of geometry indices.
- Instance-level item separation and fallible strip construction/resizing.
- Read-only access to coupled geometry, layout, snapshot and problem state.
- Correct quality-zone filtering, including zones that fully cover quadtree nodes.

## Breaking changes and migration

This release changes the shared input contract and Rust APIs and adds reflections.
Existing placement rotation and translation fields retain their meaning.

Optional `orientation.reflection_axes` lists local axes in degrees. Omitted or
empty disables reflection. Placements encode X-axis reflection before rotation
with `reflected: true`; omitted means false. Native consumers must sample both
permitted reflection states and preserve reflection when refining poses.

Strip-to-container conversion now uses `TryFrom`. `SPProblem::new`, strip resizing,
and strip fitting return `Result`. Failed resizing preserves
the existing layout. LBF's SPP constructor and solve method also return `Result`.

## Item rotations

Every item now requires an `orientation` object with an explicit `rotation`.
All angles are in degrees in the original item's coordinates.

| Permission | Rotation object |
| --- | --- |
| Fixed | `{"mode":"discrete","angles":[0]}` |
| Specific angles | `{"mode":"discrete","angles":[15,195]}` |
| Quarter turns | `{"mode":"stepped","step":90}` |
| Half turns | `{"mode":"stepped","step":180}` |
| Any angle | `{"mode":"continuous"}` |

For example, replace `"allowed_orientations": [0, 180]` with:

```json
"orientation": {
  "rotation": {"mode": "stepped", "step": 180}
}
```

Replace an omitted or null legacy orientation with explicit continuous rotation.
Replace an empty legacy list with discrete `[0]`. Legacy permission fields are
rejected, including when mixed with the new object. Unrelated item metadata is
still accepted.

Discrete lists must be nonempty and finite. Equivalent angles are normalized
modulo 360 and deduplicated. A stepped mode starts at zero, excludes 360, and must
divide a full turn. Lists and expansions are limited to 65,536 angles. The exact
step tolerance is documented on `ExtRotation`. No search or sampling mode changes
are required: stepped inputs compile into discrete rotations.

## IDs, geometry and separation

- Item IDs may be any unique `u64` values. Items carry their dense internal `idx`
  and original `external_id`. Export preserves those IDs; duplicates are rejected,
  including on zero-demand entries.
- Item polygons with holes are rejected. Container holes remain supported.
- SPP and BPP inputs accept `min_item_separation`, a finite nonnegative
  distance in input units. Omission means zero and null is invalid. Instance import
  applies it to both item and container geometry. Remove the old LBF config field.

## Rust consumers

The shared `Instance` trait is removed. Concrete instances store `Arc<Item>`;
their `item(idx)` methods return `&Arc<Item>`. Each `PlacedItem` shares its original
item through `item: Arc<Item>`, replacing `item_id`. Use `pi.item().idx()` for indexing and `pi.item().external_id()` for export.

Layouts and snapshots retain their items independently of the instance. Density,
JSON export and SVG export no longer require item lookups. `Layout::items()`
iterates distinct item types. Placement takes `&Arc<Item>` and shares it; callers
constructing items directly should wrap them in `Arc::new` once.
Concrete instances expose `item_idx` for external-ID resolution.

`Item::new` receives `idx` and `external_id`; `Importer::import_item` receives an
explicit internal index, reads the external ID from the input and returns `Arc<Item>`.
`Importer::new` no longer takes separation; direct geometry callers can use
`with_min_item_separation`, while problem import reads it from the input.
SPP warm-start import now returns a `Result` and rejects unknown external item IDs.

The in-repo LBF native and WASM consumers and bundled instances are migrated.
Vanilla sparrow adoption is prepared in a separate compatibility PR.
sparrow Pro adoption follows review of the shared contract.

## Container identity and restore

Internal containers have no ID. Bin types own `idx`, `external_id`, stock and cost;
BPP keeps a layout-to-bin-index association in both problems and snapshots. Bin
input IDs can be sparse and are preserved on export. Zero-stock entries are
omitted, and duplicate IDs are rejected before filtering.

`Layout::restore` returns `Result<(), ContainerMismatch>` and requires the containers
to share the same `Arc` base CDE. A mismatch returns `ContainerMismatch` without
changing the layout. Equal geometry constructed independently is not the same
static base. Deliberate container changes use `Layout::from_snapshot`, or an
explicit `swap_container(snapshot.container().clone())` before restore. Problem
restoration handles saved strip widths and bins explicitly at the problem level.

Generic JSON layout export takes the external container reference explicitly.
SPP uses 0 for its sole strip.
BPP uses the source bin's external ID. These serialized references are output
metadata, not collision-engine identities.

## Multi-strip packing

The `mspp` feature and `probs::mspp` module are removed. Multi-strip problem
definitions belong in their optimizer repository; generic layouts and collision
detection remain available for implementing them.

## Protected state and collision APIs

Use read-only accessors instead of public fields on Item, PlacedItem, SPolygon,
Container, InferiorQualityZone, Layout, LayoutSnapshot and CDEngine. The SPP/BPP
problem and solution types also protect their coupled fields. Accessor names match
the old field names, for example `layout.placed_items()`, `problem.layout()`,
`problem.item_demand_qtys()` and `solution.layout_snapshot()`. Remove redundant
borrows when an accessor already returns a reference.

Apply mutations through placement/removal, container-swap and problem resize
methods. For SPP, use `problem.change_strip_width(width)?` instead of separately
assigning the strip and replacing the layout container. If an optimizer also shifts
items during resize, preserve its failure and collision-tracker update order.

- Rename `Layout::is_feasible()` to `is_collision_free()`. It checks collisions,
  respecting item quality requirements; it does not check demand or orientation permissions.
- CDE snapshots, save/restore and quadtree implementation details are crate-private.
  Use Layout snapshots and restore. Public collision queries and diagnostics remain.
- Replace hazard-map indexing with `cde.hazard(key).expect("registered hazard")`
  when retrieving one hazard. Existing collector-based self-exclusion remains supported.
- Clone an item's collision shape into a reusable buffer with
  `item.shape_cd().as_ref().clone()`. Retain its surrogate. Initialize
  `TransformableFrom` destinations from the same reference geometry; matching vertex
  counts alone is insufficient.
- `fit_strip()` returns an error for an empty layout. Placement requires remaining
  item demand and bin stock; exhaustion panics instead of wrapping counters.
- BPP restore may assign new keys to recreated layouts. Its return value indicates
  changes to layout keys; do not retain stale keys across such a restore.

## Fixes and validation

Unsupported item holes, unsupported quality-zone shapes and invalid quality levels
return import errors. Container holes remain blocking regardless of item quality.
Zones meeting an item's minimum quality are ignored by collision checks. Filtering
such a zone no longer panics when it covers a complete quadtree node.

The workspace lockfile is tracked. CI covers stacked PRs, isolated library feature
combinations on the minimum Rust version and stable, strict linting, tests,
rustdoc and crate-package verification. Native development uses Rust 1.98.0;
the threaded WASM demo still uses nightly for build-std.

## Consumer checklist

1. Migrate item orientation JSON and move separation into the instance input.
2. Update Arc<Item>, idx/external_id, placement, export and restore call sites.
3. Replace field reads with accessors and use controlled methods for mutations.
4. Handle newly fallible import/strip operations and retest saved-solution round trips.
5. Test the consumer with its selected feature set before adopting 1.0.0.

Reflection support is available to library consumers but does not require enabling
reflection search in an optimizer. Vanilla sparrow remains rotation-only. Its
compatibility PR still needs the final accessor migration; sparrow-pro migration
is separate from this library release.
