# jagua-rs 2.0.0

The collision engine no longer uses a quadtree. Hazards are indexed by their bounding
boxes, sorted along the x-axis, and each hazard keeps precomputed edge geometry that
copies of it share. Queries answer the same questions through the same methods, with
collection about 2.4 times faster on the `cde_collect_1k` benchmark. Registering and
removing hazards no longer updates a tree.

This release removes configuration that only applied to the quadtree, along with
surrogate piers. Configuration JSON that still sets the removed fields keeps loading;
the fields are ignored. The instance and solution JSON formats are unchanged.

## Changes

### Collision detection

- `CDEConfig` loses `quadtree_depth` and `cd_threshold`. Its only field is
  `item_surrogate_config`.
- `HazardEntity::is_dynamic` is removed. A snapshot holds the hazards registered after
  the engine's construction; `CDESnapshot::dynamic_hazards` returns them. Hazards
  passed to `CDEngine::new` cannot be deregistered.
- `Hazard`'s fields are private. Use `Hazard::entity()` and `Hazard::shape()`.
  `Hazard::new(entity, shape)` is unchanged. Cloning a hazard shares its shape and
  edge geometry.
- `CDEngine::bbox()` still bounds the engine: shapes reaching outside it collide with
  the exterior, whatever the filter.

### Surrogates

- Piers are removed: `SPSurrogate::piers`, `SPSurrogate::ff_piers()` and
  `SPSurrogateConfig::n_ff_piers`. Surrogate detection uses the fail-fast poles only.

### SVG export

- `SvgDrawOptions::quadtree` is removed.

### Consistency checks

- `util::assertions::layout_qt_matches_fresh_qt` is renamed
  `layout_cde_matches_fresh`. `cde_matches_fresh` compares hazards and the index.
  `qt_contains_no_dangling_hazards` is removed.
- `Rect::QUADRANT_NEIGHBOR_LAYOUT` is removed.

### Geometry

- Simple polygons have a minimum edge length of `SPolygon::MIN_EDGE_LENGTH_RATIO`
  (1e-5) times their diameter. `SPolygon::new` removes every vertex closer than that to
  the previous kept vertex, and import logs a warning when it removes any. This replaces
  import's removal of consecutive duplicate vertices.
- `SPolygon` implements `TryFrom<Rect>` and `TryFrom<&Rect>` instead of `From`. The
  conversion fails for a rectangle whose short sides are below the minimum edge length.
- `fail_fast::generate_surrogate_poles` returns the poles directly instead of a
  `Result`. It stops when no further pole fits, so a thin shape can have fewer poles than
  `SPSurrogateConfig::n_pole_limits` allows. `SPSurrogateConfig::none()` now yields only
  the pole of inaccessibility, instead of one extra pole.
- `close_narrow_concavities` in `ShapeModifyMode::Deflate` closes narrow parts of the
  shape (e.g. inlets of a container). It previously required the same sign as `Inflate`,
  so it never closed anything there.
- `GeometryError` reports why a simple polygon, rectangle, circle or edge could not be
  constructed. The constructors return it inside an `anyhow::Error`; recover it with
  `downcast_ref`.

### Problems

- `bpp::io::import_solution` is removed. It was not implemented and always panicked.
- `spp::io::import_solution` returns an error for a solution that places an item more
  often than its demand, instead of panicking.

### Dependencies

- `ndarray`, `rand_distr` and `getrandom` are no longer dependencies. `web-time` is
  only a dependency on `wasm32-unknown-unknown`. On other targets `jagua_rs::Instant`
  is `std::time::Instant`, the type it already was there.
- jagua-rs no longer enables `getrandom`'s `wasm_js` feature. A WASM application that
  relied on it for its own `rand` must enable it itself.

## Fixes

- Collisions with the parts of a hazard that reach outside the engine's bounding box
  are found. The quadtree did not store those parts, so collection missed them.
- Converting an imported shape to its internal representation no longer panics when
  centering it rounds two nearby vertices onto the same point (#133). Too thin
  rectangles are an import error instead of a panic.
- Closing narrow concavities measured the area of the region it removes without the
  closing edge's end vertex. The area could get the wrong sign, which replaced a shape by
  its own concavity, and single-vertex notches were never closed.
- The centroid of a polygon far from the origin was inaccurate (a unit square at
  (4096, 4096) got (1365.3, 1365.3)), so items were not actually centered on import.
- The convex hull sorted vertices by x only, and could miss a vertex sharing its x
  coordinate with others. This made diameters too small.
- Thin shapes no longer fail to import for lack of a pole: the search for the pole of
  inaccessibility goes deeper until it finds one.
- Searching for a pole in a shape far from the origin no longer panics.
- An offset that splits a shape into disconnected parts keeps the largest part instead
  of the first, and logs an error.
- An offset whose rounding to `f32` makes its edges cross is retried with a slightly
  larger distance, so importing such an item no longer fails.

## Migration

Drop the quadtree settings from `CDEConfig` and the pier count from
`SPSurrogateConfig`:

```rust
// 1.1.0
CDEConfig {
    quadtree_depth: 5,
    cd_threshold: 96,
    item_surrogate_config: SPSurrogateConfig {
        n_pole_limits: [(100, 0.0), (20, 0.75), (10, 0.90)],
        ff_pole_area_ratio: 0.5,
        n_ff_piers: 0,
    },
}
// 2.0.0
CDEConfig {
    item_surrogate_config: SPSurrogateConfig {
        n_pole_limits: [(100, 0.0), (20, 0.75), (10, 0.90)],
        ff_pole_area_ratio: 0.5,
    },
}
```

Custom hazard entities drop `is_dynamic`. Register hazards that snapshots should leave
out, such as a container's, with `CDEngine::new`:

```rust
// 1.1.0
impl HazardEntity for MyEntity {
    fn scope(&self) -> GeoPosition { ... }
    fn is_dynamic(&self) -> bool { ... }
}
// 2.0.0
impl HazardEntity for MyEntity {
    fn scope(&self) -> GeoPosition { ... }
}
```

Read hazards through their getters:

```rust
// 1.1.0
let (entity, shape) = (hazard.entity, &hazard.shape);
// 2.0.0
let (entity, shape) = (hazard.entity(), hazard.shape());
```

Convert rectangles to simple polygons fallibly:

```rust
// 1.1.0
let shape = SPolygon::from(rect);
// 2.0.0
let shape = SPolygon::try_from(rect)?;
```
